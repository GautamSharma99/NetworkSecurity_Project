Spoofed packets lie about where they come from. The routers they cross don’t.

In a DDoS attack every packet carries a fake source address, so the victim can’t see who is flooding it. With probabilistic packet marking, each router writes its own address into a few of the packets it forwards. The victim counts those marks and rebuilds the path back to the attacker.

      How it works

      The algorithm from Savage, Wetherall, Karlin and Anderson, “Practical Network Support for IP Traceback”, ACM SIGCOMM 2000.

      1. The flood arrives with fake senders

        Attackers put a random source address on every packet. Filtering or blocking by source address does nothing, and the address says nothing about where the packet started.

      2. Routers mark a few packets

        Each router on the path writes its own address into a packet with a small probability p, such as 0.04. A later router that also marks overwrites the earlier mark.

      3. Nearby marks survive more often

        A mark from the router d hops away reaches the victim only if that router marks and the d−1 routers after it don’t:

        P(d) = p · (1 − p)d−1

        So the router next to the victim is seen most, and the farthest router least.

      4. The victim rebuilds the path

        With node sampling the victim sorts routers by how many marks it received; that order is the path. With edge sampling each mark names two neighbouring routers and their distance, so the victim joins the pieces like a chain.

      Limits worth knowing

      • Traceback finds the attacker’s first router, not the attacker’s machine. Someone still has to act at that network.
      • Routers along the path have to support marking. Paths through routers that don’t mark leave gaps.
      • The victim needs enough attack packets. A short burst may end before the farthest marks arrive.
      • Real deployments split each edge mark across eight packets to fit 16 bits, which multiplies the packets needed and adds a hash check to reject mixed fragments.
